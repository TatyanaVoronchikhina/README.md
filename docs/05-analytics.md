# Аналитика: дневные средние

В `00:10 Europe/Moscow` команда `aggregate-day` закрывает предыдущий день. При `--date YYYY-MM-DD` пересчитывает указанную завершённую дату; текущая и будущая даты отклоняются.

## Что усредняется

Ключ группы: `date + source + kind + bank + city + channel + from + to`. Банки, источники и каналы не смешиваются.

Сначала каждый банковский снимок превращается в два направления: `base → quote = buy_rate`, `quote → base = 1 / sell_rate`. Затем среднее считается отдельно для каждого направления. Обратное к среднему и среднее обратных — разные значения; используется именно среднее обратных. Для справочных строк аналогично используется `reference_rate`.

```text
average_rate = sum(directional_rates) / sample_count
```

Это арифметическое среднее успешных наблюдений, без весов по длительности. Одинаковый курс в разных запусках учитывается несколько раз; сбой импорта не добавляет нулевую точку. `sample_count` показывает полноту дня. Расчёт decimal: направленные курсы после деления имеют 18 знаков (half-even), среднее округляется до 6 знаков half-even.

## CSV и повторный запуск

Вход — `data/archive/YYYY-MM-DD/`; выход — `data/daily/YYYY-MM-DD.csv`.

```csv
date,source,kind,bank,city,channel,from,to,average_rate,sample_count,first_observed_at,last_observed_at
2026-09-09,example,bank,Example Bank,Moscow,cash,USD,RUB,80.500000,2,2026-09-09T08:00:00Z,2026-09-09T08:15:00Z
```

Синтетический пример: наблюдения 80 и 81 дают среднее 80.5. Все входные финальные файлы должны читаться корректно; при повреждении — ERROR в консоль и код 1, существующий дневной файл остаётся прежним. Пустой день создаёт файл только с заголовком и WARN. Запись атомарная; строки сортируются по ключу для воспроизводимости.

Повторный запуск пересчитывает из исходных снимков. Дневные средние — компактное представление истории для API. В этой версии сырые CSV сохраняются для пересчёта; автоматическое физическое удаление не входит в план.

## История API

`GET /v1/rates/history?from=USD&to=RUB&start=2026-09-01&end=2026-09-08` читает дневные CSV, даты включительно. Отдаёт группы отдельно с `source`, `bank`, `kind`, `city`, `channel`, `averageRate`, `sampleCount`; среднее не называется «лучшим курсом».

Период — от 1 до 31 завершённого дня. Отсутствующие дневные файлы дают `404 HISTORY_NOT_READY` с перечислением дат. Пустые сформированные дни дают пустой массив. При результате больше 10 000 точек — `400 RANGE_TOO_LARGE`, клиент сокращает период. Внутридневная история остаётся в CSV; API текущего этапа отдаёт дневную.
