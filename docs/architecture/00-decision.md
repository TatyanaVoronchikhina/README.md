# Решение: облегчённая гексагональная архитектура в плоских пакетах

Дата: 2026-09-28. Рассмотренные варианты: [трёхслойная](01-three-layer.md), [гексагональная](02-hexagonal.md), [package by feature](03-package-by-feature.md).

## Решение

Сохраняем пакеты из деревьев задач 003–006: `domain`, `config`, `logging`, `source`, `archive`, `importer`, `application`, позже `analytics` и `httpapi`. Роли пакетов соответствуют гексагональной архитектуре, а DDD применяется только тактически.

| Пакет | Роль |
|---|---|
| `domain` | ядро: `RateRecord`, `Snapshot`, инварианты, выбор предложений, decimal-арифметика |
| `importer`, `application`, (`analytics`) | прикладной слой, сценарии |
| `source`, `archive` | исходящие адаптеры |
| `cmd/currency-service`, (`httpapi`) | входящие адаптеры |
| `config`, `logging` | платформа |

## Почему

- Все сценарии работают с одной моделью и одним архивом. Поэтому вертикальные срезы (package by feature) превратились бы в один большой `shared`.
- Проект растёт прежде всего числом источников. Точка расширения — интерфейс `source.Source` и реестр `SOURCES`.
- У проекта два входа, CLI и HTTP, с одним расчётом. Поэтому сценарии отделены от транспорта (`application`).
- Один бинарник и CSV. Каталоги `adapters/inbound|outbound` дали бы вложенность без пользы и расхождение с деревьями задач.

## Правила

1. `domain` не импортирует пакеты проекта, `slog`, файлы или сеть.
2. Сценарий объявляет у себя маленький интерфейс того, что ему нужно (`importer.SnapshotStore`, `importer.BackoffStore`, `application.RecordReader`), а `archive` его реализует.
3. Адаптер источника только запрашивает и разбирает. Разбор — чистая функция `parse<Name>(io.Reader, Meta)` без сети и файлов. Инварианты записи проверяет `domain.NewSnapshot`, одинаково для всех источников.
4. Ошибка пишется в лог один раз, на границе операции: `importer` для каждого источника, команда в `cmd/` для CLI, потом HTTP-обработчик. Нижние слои возвращают обёрнутые ошибки.
5. `main.go` только читает конфигурацию, создаёт логгер и выбирает команду. Разбор флагов команд лежит в соседних файлах пакета `main`.

## Когда пересмотреть

- Появилось второе хранилище или третий вход: переходим к [полной гексагональной](02-hexagonal.md). При соблюдении правил это механический перенос пакетов.
- Появились фичи со своими данными или несколько параллельных команд разработки: переходим к [package by feature](03-package-by-feature.md).
