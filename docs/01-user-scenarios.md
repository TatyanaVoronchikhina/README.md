# Сценарии и границы сервиса

Сервис собирает опубликованные курсы и рассчитывает ориентировочную сумму обмена. Пользователь выбирает пару и канал операции; фактический обмен выполняется в банке.

## Термины и обозначения

Все термины ниже используются дальше по документу и в карточках задач; каждый вводится здесь до первого упоминания.

- **Валютная пара (`base` / `quote`)** — направление обмена. `base` — валюта, которую отдаём; `quote` — валюта, которую получаем. Пример: в паре `USD → RUB` базовая валюта `base=USD`, котируемая `quote=RUB`.
- **Канал (`channel`)** — способ проведения операции в банке. Допустимые значения: `cash` (наличные в кассе), `card` (обмен по карте), `account` (обмен между счетами). Канал обязателен для сравнения предложений: курсы разных каналов не сравниваются между собой. Внутри одного канала адаптер выбирает одну заранее определённую категорию тарифа.
- **Тип записи (`kind`)** — происхождение курса: `bank` (конкретное банковское предложение buy/sell), `reference` (официальный ориентир, например ЦБ), `market_reference` (рыночный ориентир, например биржа). В сравнении предложений участвуют только записи `kind=bank`.
- **`buy_rate`** — сколько единиц `quote` банк платит клиенту за одну единицу `base` (банк покупает валюту у клиента).
- **`sell_rate`** — сколько единиц `quote` банк требует за одну единицу `base` (банк продаёт валюту клиенту).
- **`reference_rate`** — единственный курс у записей `kind=reference` и `kind=market_reference`; полей `buy_rate`/`sell_rate` у них нет.
- **`observed_at`** — момент, когда наш сервис получил данные от источника.
- **`source_at`** — момент публикации/действия курса по данным самого источника (может отсутствовать). Свежее получение (`observed_at`) не означает свежее изменение тарифа (`source_at`).
- **Город (`city`)** — город применимости предложения. Рабочий город сервиса — Москва (`Moscow`). Если применимость к Москве не подтверждена, запись хранится с `city=unknown` и не участвует в московском сравнении.
- **`amount`** — сумма в валюте `from`, которую пользователь хочет обменять.
- **`rate`** — курс конкретного предложения, приведённый к направлению запроса (см. формулы 1–2 ниже).
- **`estimatedReceive`** — ориентировочная сумма к получению в валюте `to` (см. формулу 3 ниже).

## Сценарии

| Задача пользователя | Запрос | Результат |
|---|---|---|
| Посчитать обмен | `/v1/convert?from=USD&to=RUB&amount=100&channel=cash` | Лучшее предложение и сумма к получению |
| Сравнить предложения | `/v1/rates/best?from=USD&to=RUB&channel=cash` | Список по убыванию курса |
| Посмотреть историю | `/v1/rates/history?from=USD&to=RUB&start=2026-09-01&end=2026-09-08` | Дневные средние отдельно по каждому источнику и каналу |
| Проверить запуск сервера | `/healthz` | `200 {"status":"ok"}` |
| Найти причину сбоя | Консоль процесса или cron | JSON-запись с операцией, источником и ошибкой |

В параметрах запросов `from` и `to` — коды валют: `from` соответствует `base`, `to` соответствует `quote`.

## Охват

Город — Москва (`Moscow`), валюты — RUB, USD, EUR, BYN. Наличие валюты в списке не означает наличие предложения у каждого источника. Ориентир интерфейса — [Myfin](https://myfin.by/currency/rub); реальные источники перечислены в [каталоге](06-moscow-data-sources.md).

ЦБ, MOEX и справочные API дают ориентиры (`kind=reference` и `kind=market_reference`); банковские предложения (`kind=bank`) формируют только адаптеры банков. Каталог содержит десять банков, но наличие рабочего API с курсами у всех десяти пока не подтверждено.

## Выбор курса

Переменные этого раздела: `from`, `to`, `amount`, `channel` — параметры запроса; `buy_rate`, `sell_rate`, `observed_at`, `kind`, `city` — поля сохранённых записей (см. «Термины и обозначения»); `rate` и `estimatedReceive` — вычисляемые значения.

1. Выбрать последнюю запись отдельно для каждого источника, банка, города, канала и пары.
2. Включить только `kind=bank`, нужный город и канал; возраст успешного получения `observed_at` не больше 30 минут. Время публикации `source_at` вернуть отдельно.
3. Привести курс записи к направлению запроса. Поддерживаются только прямые пары и их обратные направления.

   **Формула 1 — курс прямой пары.** Если направление записи совпадает с запросом (`base = from`, `quote = to`), клиент продаёт `base` банку, и банк платит по курсу покупки:

   ```text
   rate = buy_rate
   ```

   **Формула 2 — курс обратной пары.** Если запись хранится в обратном направлении (`base = to`, `quote = from`), клиент фактически покупает у банка по курсу продажи, и курс в направлении запроса — обратная величина:

   ```text
   rate = 1 / sell_rate
   ```

   Деление выполняется decimal с 18 знаками и half-even; API отображает курс с 12 знаками, сумму — с двумя.
4. Ранжировать предложения по курсу, затем по свежести, названию банка и ID источника. Ранжирование выполняется до округления суммы.

   **Формула 3 — сумма к получению.** Ориентировочная сумма, которую клиент получит в валюте `to` по выбранному предложению:

   ```text
   estimatedReceive = amount × rate
   ```

   где `amount` — сумма из запроса, `rate` — курс из формул 1–2. Округление half-even до двух знаков.
5. Пустой список — `200 offers=[]`; конвертация без предложений — `404 NO_FRESH_OFFERS`.

У одинаковых валют или неположительной суммы — `400 INVALID_ARGUMENT`. Комиссии, лимиты и наличие валюты не подтверждаются; ответ содержит краткое пояснение об ориентировочном расчёте.

## При сбоях

Ошибка источника записывается в консоль, остальные источники продолжают обрабатываться. Данные предыдущего успешного импорта остаются доступны до истечения срока свежести. Ошибка чтения CSV возвращает клиенту `500 INTERNAL_ERROR`; подробности остаются в логе. Состояние источников не меняет ответ `/healthz`.
