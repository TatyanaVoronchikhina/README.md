# Сценарии и границы сервиса

Сервис собирает опубликованные курсы и рассчитывает ориентировочную сумму обмена. Пользователь выбирает пару и канал операции; фактический обмен выполняется в банке.

## Сценарии

| Задача пользователя | Запрос | Результат |
|---|---|---|
| Посчитать обмен | `/v1/convert?from=USD&to=RUB&amount=100&channel=cash` | Лучшее предложение и сумма к получению |
| Сравнить предложения | `/v1/rates/best?from=USD&to=RUB&channel=cash` | Список по убыванию курса |
| Посмотреть историю | `/v1/rates/history?from=USD&to=RUB&start=2026-09-01&end=2026-09-08` | Дневные средние отдельно по каждому источнику и каналу |
| Проверить запуск сервера | `/healthz` | `200 {"status":"ok"}` |
| Найти причину сбоя | Консоль процесса или cron | JSON-запись с операцией, источником и ошибкой |

## Охват

Город — Москва (`Moscow`), валюты — RUB, USD, EUR, BYN. Наличие валюты в списке не означает наличие предложения у каждого источника. Ориентир интерфейса — [Myfin](https://myfin.by/currency/rub); реальные источники перечислены в [каталоге](06-moscow-data-sources.md).

Канал обязателен для сравнения: `cash`, `card` или `account`. Внутри одного канала адаптер выбирает одну заранее определённую категорию тарифа. Курсы разных каналов не сравниваются. Географию источника нельзя угадывать: при неподтверждённой применимости к Москве запись хранится с `city=unknown` и не участвует в московском сравнении.

ЦБ, MOEX и справочные API дают ориентиры; банковские предложения формируют только адаптеры банков. Каталог содержит десять банков, но наличие рабочего API с курсами у всех десяти пока не подтверждено.

## Выбор курса

1. Выбрать последнюю запись отдельно для каждого источника, банка, города, канала и пары.
2. Включить только `kind=bank`, нужный город и канал; возраст успешного получения `observed_at` не больше 30 минут. Время публикации `source_at` вернуть отдельно: свежее получение не означает свежее изменение тарифа.
3. Для `base → quote`: `rate = buy_rate`; для обратной пары: `rate = 1 / sell_rate`. Только прямые пары и их обратные направления. Деление выполняется decimal с 18 знаками и half-even; API отображает курс с 12 знаками, сумму — с двумя.
4. Ранжировать по курсу, затем по свежести, названию банка и ID источника. `estimatedReceive = amount × rate`, округление half-even до двух знаков; ранжирование до округления.
5. Пустой список — `200 offers=[]`; конвертация без предложений — `404 NO_FRESH_OFFERS`.

У одинаковых валют или неположительной суммы — `400 INVALID_ARGUMENT`. Комиссии, лимиты и наличие валюты не подтверждаются; ответ содержит краткое пояснение об ориентировочном расчёте.

## При сбоях

Ошибка источника записывается в консоль, остальные источники продолжают обрабатываться. Данные предыдущего успешного импорта остаются доступны до истечения срока свежести. Ошибка чтения CSV возвращает клиенту `500 INTERNAL_ERROR`; подробности остаются в логе. Состояние источников не меняет ответ `/healthz`.
