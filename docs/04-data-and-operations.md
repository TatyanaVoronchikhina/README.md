# Хранение, запуск и консольные логи

## CSV

Один файл на успешное получение одного источника: `data/archive/YYYY-MM-DD/<source>-<UTC timestamp with nanoseconds>.csv`. Дата каталога определяется по `observed_at` в `Europe/Moscow`. Формат UTF-8, заголовок обязателен.

```csv
observed_at,source_at,source,kind,bank,city,channel,base,quote,buy_rate,sell_rate,reference_rate,source_url
2026-09-09T12:00:00Z,2026-09-09T11:00:00Z,example,bank,Example Bank,Moscow,cash,USD,RUB,80.000000,90.000000,,https://example.org/rates
```

Пример синтетический. Все курсы уже приведены к одной единице `base`; повторное деление на исходный номинал недопустимо. `buy_rate` — сколько `quote` банк платит за `base`, `sell_rate` — сколько требует за неё. Для `kind=reference` и `market_reference` заполнен только `reference_rate`, канал `reference`, банк и город могут быть `unknown`. Эти строки исключаются из лучших банковских предложений.

`observed_at` — время получения, `source_at` — время действия/публикации источника (пусто, если отсутствует). Decimal хранится строками. Для последнего курса читатель находит последнюю запись **по каждому ключу**, а не единственный последний файл во всём архиве.

Запись: временный файл в той же директории → CSV Flush → проверка ошибки → Sync → Close → rename. Читатель игнорирует временные файлы. Ошибка записи сохраняет предыдущие файлы; повреждённый опубликованный CSV вызывает ошибку операции. Одновременно разрешён один импортёр и один агрегатор; расписание не должно запускать перекрывающиеся экземпляры одной команды.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HTTP_ADDR` | `127.0.0.1:8080` | HTTP API |
| `DATA_DIR` | `./data` | Каталоги `archive/` и `daily/` |
| `SOURCES` | `cbr-xml` | Список включённых адаптеров |
| `MAX_RATE_AGE` | `30m` | Возраст получения банковского предложения |
| `LOG_LEVEL` | `INFO` | DEBUG, INFO, WARN, ERROR |

Интервал импорта 15 минут задаётся только в cron. Часовой пояс дня фиксирован: `Europe/Moscow`. Включение банков — добавление их ID в `SOURCES`; дополнительные feature flags не нужны.

## Структурный логгер

Реализация описана отдельной [задачей 002](tasks/002-console-logger.md). Стандартный `slog.NewJSONHandler(os.Stdout, ...)` из пакета `log/slog`, одна JSON-запись на строку, один `*slog.Logger` на процесс. Собственный форматтер и интерфейс логирования не нужны.

Обязательные поля: `time`, `level`, `msg`, `service=currency-service`, `operation`. Дополнительно по контексту: `source`, `error`, `http_status`, `duration_ms`, `records`, `date`, `method`, `path`. Не записывать весь ответ источника, токены или полный набор переменных окружения.

```json
{"time":"2026-09-09T12:00:00Z","level":"ERROR","msg":"source fetch failed","service":"currency-service","operation":"import","source":"tbank-public","http_status":503,"error":"unexpected HTTP status","duration_ms":124}
{"time":"2026-09-09T12:00:01Z","level":"INFO","msg":"source imported","service":"currency-service","operation":"import","source":"cbr-xml","records":4,"duration_ms":312}
```

Ошибку логирует граница операции: importer, aggregate-day или HTTP handler. Нижние слои возвращают обёрнутую ошибку; `main` не пишет её повторно. Ошибки инициализации и CLI пишет сам `main`. Успешный вывод calculate/convert остаётся отдельной строкой; LOG_LEVEL=ERROR скрывает информационные логи.

## Поведение при ошибках

| Событие | Действие | Результат |
|---|---|---|
| Таймаут / HTTP не 200 / невалидный ответ | ERROR с ID источника, пропустить весь его текущий ответ | Продолжить другие источники |
| Ошибка записи снимка | ERROR с причиной | Сохранить предыдущие данные, продолжить другие источники |
| Ошибка чтения или агрегации дня | ERROR с датой | Дневной файл не заменять, завершить команду с кодом 1 |
| Ошибка HTTP-параметров | Вернуть 400 | Сервер продолжает работу |
| Нет свежих предложений | Список 200 с пустым массивом; конвертация 404 | WARN при неудачной конвертации |
| Ошибка обработки HTTP-запроса | ERROR в консоль, клиенту 500 с общим сообщением | Сервер продолжает работу |
| Невалидная конфигурация / ошибка привязки к порту | ERROR | Завершить процесс с кодом 1 |

Один HTTP-запрос на источник за запуск, таймаут 5 секунд, немедленных повторов нет. При `429` с `Retry-After` записать `next_allowed_at` в маленький файл `data/backoff/<source>.txt`; следующие запуски пропускают запрос до этой даты и пишут WARN. Если сохранить отсрочку не удалось — завершить импорт с ошибкой. При отсутствии заголовка следующая попытка через 15 минут. Для остальных ошибок следующая попытка — по расписанию.

`import` возвращает 0, когда все выбранные источники успешно сохранены; при хотя бы одной ошибке или отсрочке — 1, после обработки остальных. Успешные снимки при этом остаются на диске.

`GET /healthz` всегда возвращает `200 {"status":"ok"}`, пока HTTP-сервер отвечает. Он не читает CSV и не обращается к источникам. Эндпоинта `/metrics` нет.

## Локальные примеры данных

Работать с ними в отдельном `DATA_DIR=./data-demo`; в `.gitignore` включить также `data-demo/`. IDs источников имеют префикс `demo-`. Синтетические примеры используются для ручной проверки поведения программы и не считаются реальными предложениями банка или подтверждением доступности API. Для свежести использовать текущее время получения в синтетических CSV, а для дневной истории — завершённую дату.

## Запуск

```bash
go build -o currency-service ./cmd/currency-service
./currency-service calculate --amount 100 --rate 80
./currency-service serve
./currency-service import
./currency-service convert --from USD --to RUB --amount 100 --channel cash
./currency-service aggregate-day --date 2026-09-09
```

Cron запускает import каждые 15 минут, aggregate-day в 00:10 для вчерашней московской даты (если `--date` опущен). В задаче поставки указать рабочую директорию, абсолютный путь к бинарнику и окружение. Вывод остаётся стандартным stdout команды; его сбор и хранение определяет хост.
