## Общие требования к результату

- Общие термины (`base`/`quote`, `channel`, `kind`, `buy_rate`/`sell_rate`, `observed_at`/`source_at`) определены в [документе 01](../01-user-scenarios.md#термины-и-обозначения); карточки задач используют их без повторного введения. Термины, специфичные для одной задачи, вводятся в её разделе «Зависимости и контракты» до первого упоминания.
- Команды собираются и запускаются по README. Конфигурация и ошибки соответствуют [документу 04](../04-data-and-operations.md).
- Критерии готовности проверяются вручную на примерах из карточек. Автотесты не входят в текущий объём.
- Результат каждой задачи: код, необходимые инструкции запуска и краткая запись выполненных команд с фактическими результатами в описании изменений.
- Для внешних API указывать дату проверки, HTTP-статус и результат разбора ответа. Недоступный источник отмечать как ограничение интеграции; обработка сохранённого ответа не подтверждает живой доступ.
- Для локальной проверки использовать отдельный DATA_DIR=./data-demo и source с префиксом demo-. Эти записи не являются реальными банковскими предложениями.
- Основные источники: ЦБ XML, зеркало ЦБ JSON, MOEX, T-Bank, Райффайзен. BanksRates и ExchangeRate-API остаются дополнительными примерами в каталоге.
- Деревья в карточках показывают накопленную структуру к этапу; README, docs и служебные файлы опущены. Число пакетов увеличивается по мере появления соответствующей функциональности.
